# Direct asset completion

User command: `In claudejones/candcgame: finish AF03.` This procedure overrides normal worker dispatch and shared-branch publication for asset-only completion. It does not change geometry, acceptance, calibration or release requirements.

1. Run current main's `node scripts/assets.mjs finish AF03`. It reads only the five-source manifest and verifies bytes. It performs no network request, generation or coordinator reconstruction. If a pinned Git object is absent, fetch only the recorded recovery branch once. If a local source is missing, recover that exact source by hash; do not silently recreate it. Report a specific unrecoverable file.
2. Work in an isolated asset checkout. Copy the verified sources to their canonical output paths without overwriting different existing files; inspect any difference first. Preserve locally recovered source bytes on the recovery branch before any editing. Update the manifest source to its remote commit/path and hash after verification. Existing `assets-original/` files remain immutable. Do not read or mutate historical coordinator jobs.
3. Inspect only the selected files. Use existing targeted PNG, seam/composite and atlas/animation checks; record actual outcomes on exact hashes. Mechanical finishing stays within ASSET_TECHNICAL_FINISHING.md. Do not iterate character-relative calibration, gameplay runs or full software regressions. One focused artistic revision after diagnosis; if still defective, show the specific defect/options rather than repeat blindly. Never mark a check passed from dimensions alone.
4. Write the existing v1 `config/asset-handoffs/af03.json` with truthful evidence and provisional metadata. Update each manifest source/hash when selecting finished bytes, so it points to the current selection. Run `node scripts/assets.mjs finish AF03 --verify`. This calls the existing targeted handoff validator, whose local cache already keys checks by bytes/dependencies. A failed handoff returns its actual failure; it does not dispatch jobs or generation.
5. Publish only the five final PNGs, v1 bundle, selected manifest and relevant evidence to `work/asset-ready/af03`. Create the dedicated branch from the reconciled asset checkout baseline using the established connector. `publishAssetOnly` in `scripts/asset-only-publisher.cjs` uses the existing connected adapter, verified local tree/blob IDs, exact allowed file paths and pinned branch head. It verifies remote blobs/tree and uses a non-force update. On retry, the exact same remote tree is success; changed heads require reconciliation. No main promotion or Pages wait occurs. Source recovery commits are separate from artwork acceptance.

Return the exact source commit plus: `In claudejones/candcgame: import asset handoff config/asset-handoffs/af03.json for AF03 from work/asset-ready/af03 at <actual commit>.` The agent substitutes the actual commit; never hand the user a placeholder. Workbench checks out that commit and uses its existing `--source-root` importer. Artwork review, calibration and gameplay release stay pending. Main/runtime publication retains its CI gates.

## Image prompts for subsequent production

`scripts/asset-prompts.mjs` is the shared image-facing template implementation for FAR, MID, GROUND, OBJECT_ATLAS and FLYING. The command resolver uses it for new production; pinned historical prompts are evidence, not rewritten in place. Keep generator input limited to that prompt and the relevant actual reference pixels. Worker safety/workflow instructions, tests, hashes, runtime transforms and unrelated stage details stay outside the image prompt. All locked visual/source contracts still apply.

The templates specify: FAR identity and repeat-safe focal placement; MID life detail, sky openings and lower overlap; GROUND material, flat surface and terrain depth; object identity, isolated cells and contact baseline; flying identity, stable body and explicit individual wing poses. `revisionPrompt` requires one observed defect and preservation scope. Use an existing layer plus a reference for edits; do not solve a configuration defect by changing artwork.

Prompt quality is not proven by template tests. Record generated attempts, defects, corrections, saved-byte reuse and elapsed production time in the next stage's existing QA record. No claim of improved image yield or fixed context capacity is made until observed.
